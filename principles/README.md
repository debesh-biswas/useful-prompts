# Principles

UX laws and heuristics. Each file has a definition, practical rules, common violations, a single-law review prompt, and cited sources.

To apply all of them at once, use [Apply UX Laws to Design](../ui-ux/apply-ux-laws-to-design.md).

| Law | In one line |
|---|---|
| [Aesthetic-Usability Effect](aesthetic-usability-effect.md) | People trust what looks good |
| [Hick's Law](hicks-law.md) | Fewer choices, faster decisions |
| [Fitts's Law](fitts-law.md) | Big, close buttons are easier to hit |
| [Jakob's Law](jakobs-law.md) | Work like the sites people already know |
| [Miller's Law](millers-law.md) | Chunk information into small groups |
| [Doherty Threshold](doherty-threshold.md) | Respond in under 0.4s |
| [Law of Proximity](law-of-proximity.md) | Related things sit together |
| [Law of Similarity](law-of-similarity.md) | Things that look alike feel related |
| [Law of Common Region](law-of-common-region.md) | A shared box makes a group |
| [Visual Hierarchy](visual-hierarchy.md) | The most important thing is the most visible |
| [Progressive Disclosure](progressive-disclosure.md) | Show details only when needed |
| [Recognition over Recall](recognition-over-recall.md) | Show options, don't make people remember |
| [Von Restorff Effect](von-restorff-effect.md) | The one thing that stands out gets remembered |
| [Peak-End Rule](peak-end-rule.md) | The best moment and the last moment stick |
| [Goal-Gradient Effect](goal-gradient-effect.md) | Show progress, people speed up near the end |
| [Serial Position Effect](serial-position-effect.md) | First and last items are remembered best |
| [Tesler's Law](teslers-law.md) | The product should carry unavoidable complexity |
| [Postel's Law](postels-law.md) | Accept messy input, give clean output |
| [Occam's Razor](occams-razor.md) | The simplest design that works wins |
| [Feedback Loops](feedback-loops.md) | Every action gets a visible response |
